# Лабораторна робота №2

Тема: Збірка проєкту за допомогою Gradle та робота з Java Collections Framework.

Мета: навчитися конфігурувати систему збірки Gradle (із використанням Version Catalogs), застосовувати стандартні колекції Java та обробляти граничні випадки.

Варіант: 22 mod 3 = 1 - Менеджер історії дій з обмеженням ємності

Виконав: Хомчук М. В., група ІП-42

## Опис предметної області та архітектури

Проєкт реалізує менеджер історії дій з обмеженням ємності (клас ActionHistoryManager у пакеті ua.kpi.comsys.collections).

Історія зберігається у двонапрямленій черзі java.util.Deque (реалізація ArrayDeque) де найновіша дія розташована на початку черги, найстаріша наприкінці. 
Нова дія додається на початок, а при перевищенні maxCapacity найстаріша дія автоматично видаляється з кінця. 
Метод undo() реалізує LIFO-поведінку, а getHistory() повертає копію історії.

Залежності керуються через Version Catalog (gradle/libs.versions.toml), використовуються лише стандартні колекції java.util.*.

## Збірка

./gradlew build

## Запуск тестів

./gradlew cleanTest test

## Тестове покриття

Тести (JUnit 5) охоплюють: 
валідацію ємності в конструкторі; 
обробку винятків для null, порожніх та пробільних дій; 
вилучення найстарішої дії при переповненні та граничні випадки ємності; 
LIFO-поведінку undo() і peekRecentAction() на порожній та непорожній історії; 
порядок і незалежність копії в getHistory(); 
роботу getHistorySize() та clear().
